# 固定版で確認した結果

2026年10月20日に、walt.id v1.2.0とProcivis One Core v1.87.2をローカルで実行しました。
両方とも正常系は受け入れ、9つの失敗入力は拒否しましたが、予定した検査で止まったことまで確認できたのはそれぞれ10件中9件です。
機械可読の記録は[implementation-status.json](../results/implementation-status.json)、依存版は[versions.json](../versions.json)にあります。

| ケース | walt.id | Procivis |
|---|---|---|
| 通常の一往復 | OSS成功、業務判定も受け入れ | OSS成功、業務判定も受け入れ |
| 開示したcourseIdの改ざん | ダイジェストと対応しない開示値を検出。ただしHTTP 503 | 必須属性の欠落としてHTTP 400。ダイジェスト不一致の拒否としては未確認 |
| 期限切れ | exp検査でHTTP 400 | Expiredを記録しHTTP 400 |
| 異なる保有者鍵 | KB署名検査でHTTP 400 | KB署名検査の失敗を記録しHTTP 500 |
| 信頼していない発行者 | OSS成功後、教材の業務判定で拒否 | OSS成功後、教材の業務判定で拒否 |
| 必須のnameを隠す | OSS成功後、教材の業務判定で拒否 | 必須属性の欠落としてHTTP 400 |

| 異なるaudience | audience検査でHTTP 400 | KBのaudience不一致を記録しHTTP 500 |
| Key Binding JWTなし | JWS構文エラーでHTTP 400。保有者鍵の検査としては未確認 | Missing key binding tokenを記録しHTTP 500 |

## 成功と数えなかった検査

walt.idのKey Binding JWTなしのケースと、Procivisの開示値改ざんのケースは`targetCovered: false`です。
それぞれ拒否されたことは確認しましたが、前者は構文解析、後者は必須属性の検査で止まっており、予定した検査項目の証拠には足りません。
この結果から、別の証明書や要求条件でも同様に拒否されると一般化することは避けています。

改ざん時のwalt.idの503、鍵や要求情報の不一致に対するProcivisの500は、教材で確認したエラー応答の特徴です。
503や500そのものを期待した拒否の証拠にせず、walt.idはAPIの診断内容、Procivisは同じリクエストIDのサーバーログで原因を確認しています。
読み取ったログはメモリ内で固定の分類へ変換し、公開結果には生ログを含めません。

## 誰が検証したか

walt.idは全ケースでWallet2が受領、保存、提示データの作成を行います。
テスト用Pythonが失敗条件を加え、Verifier2へ送ります。

ProcivisはCore自身のウォレットによる正常な一往復を別に実行し、10ケースではPythonの保有者クライアントを使います。
これは、鍵や要求情報だけを変えた提示を作るための実験用コードです。
両実装のウォレットが同じ機能を持つことや、異なるOSS同士の接続を確認した実験ではありません。

信頼する発行者、対象コース、申込者名は教材の追加処理で確認します。
この処理へ渡すのはOSSが成功とした提示だけであり、HTTP 200だけで業務上も受け入れられると判断しない構成にしています。

期限切れの作り方は異なります。
walt.idは過去のiatとexpで発行し、Procivisはschemaへ1秒の有効期間を設定して発行後に待ちます。
どちらも発行済みの署名を書き換えず、許容時刻差の2秒を超えてから検証しています。

## 再現と記録

[README](../README.md)の手順を実行した後、次のコマンドで結果を再生成できます。

```sh
.venv/bin/python scripts/report.py
```

発行者と保有者の鍵、nonce、証明ID、署名は実行ごとに変わります。
比較するのはバイト列の一致ではなく、開示項目、拒否した検査、OSSの状態、業務判定です。
主教材は、これらの結果と実装量、必要な運用を見て著者が選びます。
